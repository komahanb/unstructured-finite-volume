# Graph Time Integrator architecture

Status: implementation handoff draft  
Target repository: `komahanb/unstructured-finite-volume`  
Initial implementation target: Phase 1 only  
Kernel rule: do not edit `src/fractal_graph.f90`

## 1. Purpose

Publish a small public interface where users plug in:

```text
R  residual / constraint form
F  functional / objective form
partials of R and F up to derivative degree r
```

The GTI layer owns:

```text
time graph construction
scheme coefficients
Newton solve wiring
linear solve wiring
forward traversal
reverse traversal
higher-order chain-rule assembly
heterogeneous scheme boundaries
adaptive trajectory growth
```

The public user should not derive or implement:

```text
BDF adjoint
DIRK adjoint
ABM adjoint
scheme-specific tangent equations
boundary terms between scheme families
higher-order chain-rule bookkeeping
```

## 3. Core mathematical split

A local differentiable form is:

```text
Phi(U, xi, t)
```

where:

```text
U  = (q, qdot, qddot) for second-degree systems
xi = design variables or design fields
t  = time
```

More generally:

```text
U = (q^(0), q^(1), ..., q^(d))
```

where `d` is the differential degree of the governing equation.

Residual and functional forms share the same kind of interface:

```text
R_form : state/design/time -> residual output
F_form : state/design/time -> functional output
```

They differ by use, not by ontology:

```text
R value            drives the constraint solve
R first partials   build the Newton Jacobian
R higher partials  enter higher-order chain-rule assembly

F value            contributes to the time functional
F first partials   seed tangent/adjoint reductions
F higher partials  enter higher-degree functional contractions
```

## 4. Fractal graph placement

There are three levels.

### 4.1 Kernel identity

`fractal_graph::graph` remains the identity object.

Do not add to it:

```text
parent pointer
ambient set
scheme kind
time index
stage index
state values
residual pointer
functional pointer
Jacobian pointer
solver pointer
derivative degree
```

### 4.2 Relation view

The GTI time view is:

```text
G_time = (S_time, R_time)
```

where:

```text
S_time = time/state/stage instances
R_time = declared dependencies among those instances
```

The graph kernel provides identity. The GTI view provides interpretation.

### 4.3 Form view

A form is viewed as:

```text
Phi : B1 -> B2
```

where:

```text
B1 = argument graph
B2 = output graph
```

For GTI:

```text
R_form : B_state_design_time -> B_residual
F_form : B_state_design_time -> B_functional
```

## 5. Public user interface target

Conceptual use:

```fortran
call problem % set_residual   (R)
call problem % set_functional (F)
call problem % set_design     (xi)
call problem % set_initial    (initial_state)

call driver % solve(problem, scheme_control, derivative_degree=r, result=out)
```

Explicit heterogeneous schedule:

```fortran
call trajectory % append_window(SDIRK4(), t0=0.0_dp, t1=0.5_dp, h=0.025_dp)
call trajectory % append_window(BDF4(),   t0=0.5_dp, t1=1.0_dp, h=0.020_dp)
call trajectory % append_window(ABM4(),   t0=1.0_dp, t1=1.5_dp, h=0.0125_dp)

call driver % solve(problem, trajectory, derivative_degree=r, result=out)
```

Adaptive schedule, later:

```fortran
call driver % solve(problem, adaptive_controller, derivative_degree=r, result=out)
```

The adaptive controller chooses the next scheme and step size. The GTI layer appends a valid time graph.

## 6. Public differentiable form interface

### 6.1 Abstract form

```fortran
type, abstract :: gti_differentiable_form
contains
   procedure(form_name_interface)            , deferred :: name
   procedure(form_input_signature_interface) , deferred :: input_signature
   procedure(form_output_signature_interface), deferred :: output_signature
   procedure(form_max_degree_interface)      , deferred :: max_degree
   procedure(form_value_interface)           , deferred :: value
   procedure(form_partial_action_interface)  , deferred :: partial_action
end type gti_differentiable_form
```

### 6.2 Value call

```fortran
subroutine value(this, point, output)
   class(gti_differentiable_form), intent(in)    :: this
   type(gti_evaluation_point)    , intent(in)    :: point
   type(gti_value_buffer)        , intent(inout) :: output
end subroutine value
```

For `R_form`, `output` is residual data.

For `F_form`, `output` is scalar or small-vector functional data.

### 6.3 Partial-action call

The user supplies multilinear actions, not full tensors by default.

```fortran
subroutine partial_action(this, point, request, directions, output)
   class(gti_differentiable_form), intent(in)    :: this
   type(gti_evaluation_point)    , intent(in)    :: point
   type(gti_partial_request)     , intent(in)    :: request
   type(gti_direction_bundle)    , intent(in)    :: directions(:)
   type(gti_value_buffer)        , intent(inout) :: output
end subroutine partial_action
```

Meaning:

```text
order = 0: Phi(U, xi, t)
order = 1: D Phi [v1]
order = 2: D² Phi [v1, v2]
order = k: Dᵏ Phi [v1, ..., vk]
```

Each direction specifies the perturbed argument:

```text
state component q
state component qdot
state component qddot
design xi
time t, optional
geometry/mesh data, later if needed
```

This supports mixed partials without publishing explicit tensor storage.

## 8. Evaluation point

A form sees a local point, not the whole trajectory.

```fortran
type :: gti_evaluation_point
   type(gti_state_bundle)  :: state
   type(gti_design_bundle) :: design
   real(dp)                :: time = 0.0_dp
   integer                 :: window_id = 0
   integer                 :: step_id = 0
   integer                 :: stage_id = 0
   class(gti_geometry_view), pointer :: geometry => null()
end type gti_evaluation_point
```

The `geometry` pointer is optional. It permits FV coupling without making GTI own mesh concepts.

The form must not see:

```text
global sparse matrix structure
time graph storage
optimizer
adjoint vector
partition map
solver internals
```

## 9. State and value storage

Do not write:

```fortran
type(graph_field) :: q
```

because `graph_field` is an abstract interface.

Use slots that can hold a concrete field polymorphically:

```fortran
type :: gti_field_slot
   class(graph_field), allocatable :: value
end type gti_field_slot
```

State bundle:

```fortran
type :: gti_state_bundle
   type(gti_field_slot), allocatable :: component(:)
contains
   procedure :: differential_degree
   procedure :: has_component
end type gti_state_bundle
```

Convention:

```text
component(1) = q
component(2) = qdot
component(3) = qddot
```

The mathematical index can still be written as `q^(0), q^(1), q^(2)`. The Fortran storage is one-based.

Design bundle:

```fortran
type :: gti_design_bundle
   type(gti_field_slot), allocatable :: component(:)
contains
   procedure :: size
   procedure :: has_entries
end type gti_design_bundle
```

Value buffer for Phase 1:

```fortran
type :: gti_value_buffer
   integer :: value_kind = GTI_VALUE_REAL
   integer :: nentries = 0
   integer :: ncomp = 1
   real(dp), allocatable :: rvals(:)
contains
   procedure :: clear
   procedure :: set_real
   procedure :: get_real
end type gti_value_buffer
```

A later PR may adapt `gti_value_buffer` to `class_graph_field::field` when GTI connects to the existing graph field layer.

## 10. Time graph

### 10.1 Sets

```text
S_state_instance      every q/qdot/qddot state instance at a step or stage
S_window              integration windows
S_scheme              scheme motifs used by windows
S_design              design variables or design fields
S_functional_output   scalar/vector functional outputs
S_residual            residual equations at fixed-point vertices
```

### 10.2 Relations

```text
R_history        previous states feeding current state
R_stage          stage-to-stage dependencies inside a multistage scheme
R_self           fixed-point self coefficient for Newton vertex
R_sink           stage/history values producing end-of-step state
R_boundary       transfer from one window to the next
R_quadrature     state/stage vertices contributing to F
R_design         shared design referenced by windows
```

### 10.3 Coefficient fields

Numerical coefficients live as fields on relation entries:

```text
alpha coefficients
beta coefficients
h, 1/h, 1/h² factors
quadrature weights
boundary transfer weights
```

They do not live inside `graph`.

### 10.4 Self-relations

Self-relations are allowed for fixed-point coefficients.

```text
topological order ignores R_self
Newton/Jacobian assembly uses R_self
```

## 13. Solver adapters

GTI should hook existing Newton and linear solvers through adapters.

Nonlinear solver adapter:

```fortran
type, abstract :: gti_nonlinear_solver
contains
   procedure :: solve_vertex
end type gti_nonlinear_solver
```

Linear solver adapter:

```fortran
type, abstract :: gti_linear_solver
contains
   procedure :: solve
end type gti_linear_solver
```

Use cases:

```text
primal:   nonlinear solve at fixed-point vertex
tangent:  J  * delta  = rhs
adjoint:  Jᵀ * lambda = rhs
```

Existing graph Newton and linear solver classes should be wrapped. GTI must not force one solver implementation.

## 14. Traversals

### 14.1 Forward traversal

```text
for vertex in forward_order:
    gather predecessor states through R_time
    build scheme state approximations
    call nonlinear solver on R_form
    store converged U^(0)
    evaluate or defer F_form contribution
```

### 14.2 First tangent traversal

For one design direction `p`:

```text
for vertex in forward_order:
    assemble incoming tangent contributions
    add design source DR[Dxi p]
    solve J * U^(1) = -rhs
    store U^(1)
```

Functional directional derivative:

```text
sum over vertices of DF[U^(1), p]
```

### 14.3 First adjoint traversal

```text
for vertex in reverse_order:
    gather successor adjoint contributions through transposed R_time
    add functional seed from F partials
    solve Jᵀ * lambda = rhs
    accumulate design-gradient contribution
```

No scheme-specific tangent or adjoint classes.

## 15. Higher-degree directional derivatives

Derivative degree is `r`.

Stored directional state derivatives:

```text
U^(0) = primal state
U^(1), ..., U^(r-1) = directional state derivatives
```

For each degree `s = 1, ..., r-1`:

```text
for vertex in forward_order:
    rhs = chain_rule_rhs(R_form, degree=s, lower_states=U^(0:s-1), design_direction=p)
    solve J * U^(s) = -rhs
```

Then one reverse traversal performs the degree-`r` functional contraction.

Core invariant:

```text
same primal Newton Jacobian J at every derivative degree
new degree only changes the right-hand side
```

## 16. Higher-order chain-rule assembler

```fortran
type :: gti_chain_rule_assembler
contains
   procedure :: residual_rhs
   procedure :: functional_seed
   procedure :: required_partials
end type gti_chain_rule_assembler
```

Residual RHS:

```fortran
subroutine residual_rhs(this, form, degree, point, lower_state_derivatives, design_dirs, rhs)
```

This computes all chain-rule terms for:

```text
D^degree R(U(xi), xi)
```

except the term containing the unknown highest state derivative. The excluded term is represented by:

```text
J * U^(degree)
```

Functional seed:

```fortran
subroutine functional_seed(this, form, degree, point, lower_state_derivatives, design_dirs, seed)
```

Required partial discovery:

```fortran
call chain_rule % required_partials(degree=r, requests=reqs)
```

The driver validates that `R` and `F` support every request before solving.

## 20. Sanity checks before computation

Form checks:

```text
R output dimension matches residual equation set
F output dimension matches functional output set
R supports required partial actions up to degree r
F supports required partial actions up to degree r
state bundle has components required by differential degree d
design bundle has required entries
```

Scheme checks:

```text
motif has valid coefficient fields
required history is available
fixed-point vertices have one primary unknown
self-coefficients exist where Newton needs them
quadrature relation is complete
```

Trajectory checks:

```text
windows cover requested time interval
window boundary ports match
history transfer satisfies next-window history requirement
R_self excluded from topological ordering
R_time is acyclic after excluding self-relations
adaptive extension preserves all above after each accepted step/window
```

Solver checks:

```text
nonlinear solver available for fixed-point vertices
linear solver available for J and Jᵀ actions
transpose mode supported or explicitly emulated
Jacobian cache policy declared
```

## 25. One-sentence architecture

GTI turns user-supplied differentiable residual and functional forms into a time-relation graph, then evaluates primal states, tangent states, adjoints, and higher-degree directional derivative contractions by traversing that relation instead of deriving scheme-specific sensitivity code.
